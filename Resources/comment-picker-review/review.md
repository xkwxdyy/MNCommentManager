# 评论选择器与滑轨定制功能审查

日期：2026-10-18。范围：分析用户提供的安装包，不实施修复，不安装，不重启 MarginNote。

## 功能与实现

定制包在单卡片旁新增“↕”浮动按钮。卡片至少有两条可移动评论时，按钮打开原生评论列表；选中评论后出现位置滑轨。拖动圆点时只更新目标位置，松开后提交移动；点击刻度直接提交移动。移动完成后重新打开滑轨，便于继续调整。该入口只调整当前卡片内单条评论的顺序。

评论列表显示序号、类型和文字摘要，没有图片缩略图。移动逻辑调用已有的 `CommentMutations.moveComments`，沿用原生刷新与撤销分组，不新增持久化数据。管理与添加入口仍由原配置控制；移动入口没有独立开关。

安装包沿用正式版本的 addonid 与 0.1.28 版本号。安装该包会替换同标识的正式插件，版本号无法区分定制版和正式版。

## 需要修复的缺陷

### 1. 评论顺序变化后可能移动错误的评论

位置：`readable/custom/DynamicCommentActions.js:482`、`:723`。

列表按钮只保存卡片标识、卡片会话 token 和评论索引。滑轨另外保存评论数量；提交前只核对 token 和数量，没有核对评论身份或列表版本。卡片 token 只随单卡菜单通知更新，无法识别同一卡片的同步、撤销或其他入口造成的评论顺序变化。

复现：原顺序为 A、B、C，选择 A 并打开滑轨；随后把底层顺序改为 B、A、C，评论数量保持不变。将滑轨移至末尾，实际被移动的是 B，结果为 A、C、B。列表显示后、点击列表行前发生相同变化，也会选错评论。

最小修复：打开列表时保存评论列表版本或完整顺序签名，选择列表行和提交移动时读取最新数据并校验；发生变化时刷新列表并要求重新选择。只有数量校验不足以保证操作目标一致。

### 2. 选择器关闭与卡片切换未完整清理状态

位置：`readable/custom/DynamicCommentActions.js:880`、`:884`、`:915`。

打开选择器或滑轨后，交互保护期延长至一天；原生菜单关闭回调发现选择器仍在显示便直接返回。关闭选择器仅移除面板并把保护期改为 900 毫秒，没有重新安排隐藏或清理操作。模拟等待两秒后，管理与移动按钮仍然显示，旧卡片上下文仍然保留。

切换至另一张单卡时，代码替换当前上下文但保留旧选择器。模拟中，列表仍显示卡片 one，当前上下文已变为 two；点击旧行被 token 校验拒绝。该校验能够阻止跨卡片写入，但界面已失效，浮动按钮也因旧面板存在而无法重新定位。

最小修复：切换单卡上下文前关闭旧选择器；关闭选择器时根据原生菜单状态清理上下文和按钮，或者补充有 token 校验的延迟清理。关闭笔记本、场景切换及异常退出路径也应复用该清理。

### 3. 固定宽度导致窄窗口关闭入口越界

位置：`readable/custom/DynamicCommentActions.js:422`、`:438`、`:563`。

选择器和滑轨宽度固定为 360，定位函数只限制起点，没有缩小面板。320 宽的宿主窗口中，模拟面板位置为 x=8、width=360，右侧越界 48；关闭按钮使用固定 x=312，相对宿主从 x=320 开始，关闭入口完全超出宿主宽度。窗口变化回调也没有重新布局该面板。

最小修复：面板宽度取可用宽度与 360 中的较小值，内容与关闭入口随面板宽度布局；窗口变化时重新布局或关闭后重开。高度下限及分屏场景一并验证。

## 包体一致性与性能建议

- 定制包的备用更新清单从正式包内的 0.1.27 回退到 0.1.22，近期下载历史随之缺失。正式整合时应恢复基准清单；本次未测试更新器消费该清单的真实行为，不推断会自动降级。
- 为判断移动按钮显隐，布局函数会调用完整 `getNoteSnapshot`，同一轮定位存在重复调用。快照包含评论媒体序列化等处理，而此处只需要评论数量或移动能力。建议改为轻量读取，避免把完整序列化加入按钮定位。尚未进行真实设备性能测量，不把该建议列为已证实的卡顿。
- `runMoveComment` 与对应 selector 已加入，但当前选择器和滑轨没有调用该入口。整合时可删除该未使用路径，减少同一操作的重复入口。

## iPad 反馈的证据边界

[Issue #67](https://github.com/xkwxdyy/MNCommentManager/issues/67) 的外部评论报告同类定制功能在手机显示正常、iPad 全部动态按钮不显示。该信息属于设备反馈，不能代替本次独立验收，也不能仅凭功能一致认定附件与评论者测试包的二进制一致。

本次确认新增移动入口把有多条评论时的按钮组宽度从 92 增至 140，仍沿用正式包的 `FloatingControlLayout`。共享布局在扫描超出预算或找不到位置时返回空值，动态按钮随之整组隐藏；入口还沿用窗口对象严格全等检查。上述分支与设备反馈相关，但尚无 iPad 日志证明实际触发分支。

后续诊断应只增加显示路径日志，记录通知接收、窗口匹配、卡片和锚点解析、布局扫描数量与超限状态、最终位置结果。取得触发证据后再修改显示逻辑。不能把滑轨手势问题直接当作“按钮全部不显示”的原因。
