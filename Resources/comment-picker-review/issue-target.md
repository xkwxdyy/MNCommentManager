## 已复现的问题

评论选择器仅保存卡片 token 和评论索引；滑轨提交前另外核对评论数量。相同卡片内评论顺序改变但数量不变时，旧索引仍被用于提交。

原顺序 A、B、C，选择 A 后打开滑轨；底层改为 B、A、C。将滑轨移至末尾，实际移动 B，结果为 A、C、B。列表显示后、点击行前改变顺序，也会选错评论。

## 根因与建议

卡片 token 无法表示评论列表版本，数量也无法表示评论身份和顺序。列表打开时保存顺序签名，在选择评论和最终提交时读取最新数据并校验；列表变化时刷新并重新选择。
