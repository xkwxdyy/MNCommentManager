## 问题描述

2026-10-18 用户反馈：点击 Markdown 链接解析结果中的 MarginNote 卡片链接定位按钮，界面显示“编辑请求已过期，请重新打开编辑器”。

## 根因与影响

定向编辑会话把正在编辑的卡片固定为 A。`focusLinkedNote` 的 `payload.noteId` 表示链接目标 B，但 `ExternalCardEditor.validateCommand` 对全部带卡片标识的命令统一要求目标等于 A，导致合法导航被误拒绝。普通链接、Markdown 正文链接及提取结果定位共用该命令，均受同一校验影响。

已通过生产 Bridge 分发、命令处理和定位函数的隔离模拟复现相同的 `STALE_REQUEST`；该证据不代表真实设备验收。

## 修复范围

仅允许 `focusLinkedNote` 使用不同的链接目标；定向编辑会话不变，刷新继续读取 A。修改评论、删除、移动、修改链接及批量命令继续受到原有目标限制。

相关历史：[链接交互 Issue #39](https://github.com/xkwxdyy/MNCommentManager/issues/39)。本次为新增定向编辑协议后的独立回归。

## 本轮验证

- 修复前，新增回归脚本复现定位 B 被错误拒绝。
- 修复后，生产 Bridge 模拟验证主脑图和浮窗导航、原窗口选择、导航后的固定目标刷新、跨卡片写入阻挡、批量限制及普通面板导航通过。
- 定向编辑生命周期、Bridge 请求生命周期、普通链接与 Markdown 链接键盘检查通过。
- 源码语法与差异空白检查通过。
- 测试包验证及本机安装结果后续补充；实际 MarginNote 定位、长按浮窗与设备验收仍待完成。
