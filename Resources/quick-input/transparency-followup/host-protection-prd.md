# 顶栏保护适配方案

MN5 沉浸模板在插件窗口与顶部胶囊保护区域重叠时降低插件视图的透明度。宿主开发者报告上限已由0.25调整为0.6，并加入有限次数的提示，但代码提交不代表当前宿主已上线。插件适配应减少与保护区域的重叠，保持宿主提示、透明度恢复和用户交互一致。[开发者说明](host-developer-report.md)

## 问题与成功标准

快速输入框目前使用覆盖整个学习区域的原生父视图，网页中的输入卡片位于其内部。输入卡片在中央不代表原生父视图没有遮挡顶部胶囊；该父视图是否正是宿主保护的识别对象，仍需真实宿主验证。仅把父视图移到窗口层级不能证明重叠已经消除。[当前原生布局](QuickCommentController.js)

正常打开、重开和调整窗口尺寸后，快速输入框的原生父视图、WebView及其背景均不进入顶部保护区域，文字和按钮清晰可见，顶部工具栏继续可操作。主面板的默认布局和最大化范围避让顶部，手动拖动仍保持自由。草稿、中文组词、键盘收起、保存退场和提交去重保持现有行为。

## 范围与约束

仅处理 MN Comment Manager 的快速输入框与主面板布局。第三方插件、宿主代码、工作流业务逻辑和持久化数据不在本轮修改范围。现有同步冲突与无关改动继续保留；此前的独立测试包和原工作流备份继续保留。2026-10-13，用户通过“先尝试修复吧”确认尝试实施，并随后要求使用脚本更新。源码、测试包与本机脚本安装已完成；本轮不包含提交、推送或发布授权。

插件不通过反复写入alpha、提高图层位置或重新置顶来对抗宿主保护，也不增加重复提示。入场和退场动画中的主动透明度变化仍作为插件的正常行为验证。宿主的0.6上限不是插件应当固定设置的透明度，原本低于该值的动画状态继续保留。

## 初步方案

### 快速输入框

优先获取当前插件窗口中真实的顶部胶囊保护区域，把该区域转换为当前原生父视图使用的坐标，并以保护区域下方的内容区域作为输入覆盖层的frame。WebView同步采用该范围，网页继续使用其本地viewport布局。仅给网页增加顶部padding不能改变原生父视图的重叠，因此不能作为独立修复。

目标卡片位置继续通过原生视图间的坐标转换取得，避免缩小覆盖范围后保存退场的终点发生偏移。键盘通知、原生下移动画、旋转、分屏和外接键盘须按新的局部坐标复验。输入关闭期间继续冻结布局，旧会话与迟到事件不影响新窗口。

此前的窗口挂载改动保留为实验记录，不能继续作为已经解决透明问题的证据。确定覆盖范围后，再比较窗口挂载和内容视图挂载的必要性；本轮不增加强制置顶操作，也不未经验证自动回滚当前已安装版本。

### 主面板

首次默认布局和最大化范围采用顶部保护区域下方的内容区域。恢复已有窗口位置时，在显示范围内进行必要的避让，不覆盖原始保存位置；只有用户后续主动拖动或调整尺寸时才按现有规则保存新位置。

保留手动拖动自由。手动拖入保护区域后，宿主可以调低透明度并提示；插件不强行调亮或自动移走该窗口。该选择允许用户临时重叠，代价是仍可能出现宿主预期的半透明状态。如需禁止拖入保护区域，需要另行确认交互选择。

### 保护区域的读取

本地 MNUtils 中存在顶部胶囊位置工具，但该实现使用当前焦点窗口、固定子控制器索引、固定兜底高度与跨调用缓存，不能直接视为多窗口和动态布局的可靠边界。现有本地头文件和本次文档检索尚未确认宿主导出的正式保护区域接口。

实施前优先核实宿主是否提供按窗口读取保护区域的接口。若只能使用兼容定位，必须校验窗口归属和坐标、在布局变化时重新计算，并保留诊断；不把固定65或70像素当作已确认契约。缺少边界证据时先完成可独立验证的坐标与布局草案，依赖该边界的实际适配不能宣称完成。

## 验证与待解决问题

自动回归覆盖保护区域与原生视图的相交判断、窗口坐标转换、窄屏与低高度、最大化和恢复、已有位置保存、键盘动画及草稿安全。增加非重叠的居中输入卡片但原生父视图重叠的模拟，区分网页位置和宿主识别范围。

真实宿主分别记录安装版本及是否包含hg 21156、21171。MN4与MN5均需复验移入和移出保护区域、主面板拖动、快速输入连续打开关闭、中文输入法、键盘收起、弹窗、暂停和恢复、旋转、分屏和多窗口。旧宿主的0.25行为与新版宿主的0.6行为分开记录，不把新版宿主的改善计为插件单独修复。

当前实现通过MNUtils定位当前窗口的顶部胶囊视图，校验窗口归属并在每次布局时重算几何范围，额外保留8点间距。正式保护区域接口与宿主识别范围仍待核实，实际透明度尚未验收。实现、安装与验证见 [本轮记录](top-chrome-avoidance/validation.md)。

宿主说明与方案状态已同步到 [Issue #71](https://github.com/xkwxdyy/MNCommentManager/issues/71#issuecomment-6144204415)，问题保持开放。
