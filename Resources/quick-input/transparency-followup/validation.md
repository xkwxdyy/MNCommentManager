# MN5 透明问题后续排查

日期：2026-10-13。关联 [Issue #71](https://github.com/xkwxdyy/MNCommentManager/issues/71)。

## 已知事实与判断边界

用户再次反馈快速输入框整体高度透明；截图中的标题、正文和按钮同时变淡。此前调整学习视图内部的插入位置未解决实际问题。本机观察也出现其他插件面板整体变淡，但直接挂到窗口的日志面板清晰可见。该差异支持检查学习内容视图的显示处理；目前没有取得宿主修改透明度的调用或有效的透明度日志，不能把该判断写成已确认根因。

此前的独立工作目录已不存在。此次从 v0.1.26 和完整的 keyboard-safety-review/implementation.patch 恢复验证副本，原工作目录的工作流业务源码及同步冲突均保留。

本机安装文件另已被 0.1.25 工作流测试版替换。该版本的 main.js 没有加载 QuickCommentController，不能把现有磁盘文件视为完整的快速输入审查版。此前运行中的窗口是否仍使用旧控制器，尚未取得决定性证据。安装历史已从“支持工作流菜单自定义”聊天和本机文件核实。

## 局部修复方案

输入框挂到其所属窗口，位于学习区域所属的窗口子视图上方，保留其他窗口覆盖视图顺序。布局把学习区域的 bounds 转换为同一窗口的坐标，输入框继续覆盖学习区域；重复打开不强制移到最顶层。无法识别窗口归属时沿用原内容定位方案。代码不修改宿主或其他插件的透明度，已有关闭动画、键盘事件和草稿逻辑继续保留。

新增模拟在旧代码下首先因输入框仍位于学习视图内而失败。修复后，学习区域的父视图透明度降低不会影响输入框；偏移、尺寸变化、重复打开、宿主覆盖顺序及主动关闭渐隐均通过。这些结果证明局部方案的代码行为，不能替代 MN5 实际显示验收。
