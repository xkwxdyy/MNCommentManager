# 快速输入的数据处理审查与验证

日期：2026-10-12。审查范围：重复提交、草稿保留、保存失败与相关异步时序。假设为单个用户在各插件窗口内操作，窗口之间分别保存会话。原生数据库由 MarginNote 管理。

## 已复现并修复的问题

| 优先级 | 原有风险 | 修复后的行为 |
| --- | --- | --- |
| P1 | 初始化未完成时关闭窗口会发送空文本，可能覆盖已有原生草稿；旧草稿请求及旧关闭快照也可能覆盖最新正文 | 未初始化时不发送正文；草稿使用递增版本号；关闭冻结输入并保留最新快照，旧版本不能覆盖新版 |
| P1 | 换行后立即关闭，读取尚未更新的页面值可能丢失刚插入的内容 | 关闭和提交使用同步保存的最新文本；中文组词期间单独保留输入框中的当前文字 |
| P1 | 原生层只保存最近一次提交，历史失败请求在后续失败后重放可能被重新执行 | 会话按提交标识保留完整结果；已知请求只返回原记录，不再次追加 |
| P1 | 查询暂未观察到请求时允许修改正文，原请求稍后成功可能被错误地应用到新正文 | 未确认的提交保持原标识、原正文和原草稿版本，只允许核对或重试同次提交 |
| P1 | 旧失败回执迟到时可能解锁后续提交；成功回执只核对卡片标识，未核对原正文 | 回执必须对应当前提交标识和原正文；旧提交回执不能改变新提交状态 |
| P2 | 关闭失败会错误恢复为编辑状态；动画准备异常可能阻止已保存窗口关闭 | 关闭失败恢复原编辑或待核对状态；动画异常保持保存结果并继续关闭 |

修复前，初始化关闭、未知请求编辑、乱序草稿及立即换行关闭的回归测试均失败。修复后，上述测试通过。相关缺陷分别记录在 [Issue #65](https://github.com/xkwxdyy/MNCommentManager/issues/65) 和 [Issue #66](https://github.com/xkwxdyy/MNCommentManager/issues/66)，真实设备验收完成前保持开放。

## 提交与保存约定

- 写入前失败允许保留正文、修改正文并创建新的提交标识。
- 写入可能已经发生时，不创建新的追加请求；核对或重试仍使用原提交标识和原正文。
- 没有观察到提交记录不等于请求已经取消，输入区继续保持原正文。
- 只有对应提交标识、正文及目标卡片的成功回执能够触发成功动画和关闭。
- 关闭前保存的最终草稿快照不接受后续旧写入，初始化读取失败也不清空原生草稿。

新增草稿字段为 `draftRevision`，新增提交记录字段为原正文和该版本号。修改仍通过现有 Bridge 命令完成，没有新增存储系统或编辑器依赖。会话与历史提交记录在当前窗口内保存，确认保存并关闭后释放。

## 本次验证

- 完整前端测试通过 189 项，其中快速输入专项测试通过 21 项。
- Node 回归检查通过 54 个脚本；原生快速输入脚本另行复验通过。
- 正式构建页面通过尺寸、深浅主题、减少动态效果、草稿重开及定向动画检查。控件尺寸在进入动画结束后测量，浮点误差容差为 0.01 像素。
- 前端与实际原生源码在受控 Native 对象下完成联合模拟：未送达后重试、已经保存但回执丢失后重试、追加后保存失败再核对，均只新增一次评论；延迟草稿写入不会覆盖关闭快照，重新打开恢复最终正文。
- 本次没有改动真实 MarginNote 数据。联合模拟使用原生脚本的 VM 测试环境，不能代替真实数据库、键盘或设备验收。

测试结果位于 `review-native-results.json`、`review-browser-layout.json` 和 `review-browser-failures.json`。包内校验与摘要另存为 `review-package-report.json`。
