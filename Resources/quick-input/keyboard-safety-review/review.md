# 快速输入草稿与连续操作安全审查

日期：2026-10-13。审查范围为本次层级与键盘联动改动，重点检查连续打开关闭、中文组词、收起键盘、草稿恢复和同次提交重放。源码仍以完整 v0.1.26 独立工作目录为基线；此次未覆盖原工作目录的其他业务改动。

## 审查发现与修复

### 中文组词快照可能读取旧正文

组词结束事件先于最终输入事件到达时，原关闭流程只检查当前组词标记，可能读取尚未更新的正文引用。键盘隐藏先于组词结束时，关闭快照也会提前读取拼音内容。失败测试已分别复现该路径。

组词结束处理现在立即同步输入框中的最终文字；关闭期间若组词仍在进行，先等待组词结束，并留出一次事件循环处理最终输入事件，再取得关闭快照。等待超过500毫秒时保留最新可见正文、显示提示并允许再次关闭，不直接移除输入框。等待期间提交入口保持禁止，结束组词的回车不会被当成新增评论；页面卸载会取消等待。

### 关闭失败可能使正文恢复为旧内容

组词期间关闭请求失败后，旧实现更新了正文引用，却未同步 React 显示状态，页面重绘会恢复旧正文。失败测试已复现该问题。

正文快照与显示状态现在同步更新；组词完成后的关闭失败继续保留最终正文，重试关闭使用同一份最新文本。减少动态效果与普通动画下的包内浏览器联合模拟均验证关闭失败后正文可见、可以再次关闭，重开后仍恢复正文与 Markdown 模式。

### 保存开始与键盘收起竞争可能提前关闭窗口

提交刚开始或同次提交重试刚开始时，界面的“保存中”状态尚未完成渲染。若同一轮事件内键盘隐藏或关闭按钮随后触发，旧检查仍把窗口视为可关闭。失败测试已复现提前发出关闭请求。

关闭入口现在同步检查提交记录与编辑锁，提交及重试开始时立即更新保存状态，避免依赖尚未渲染的状态。保存结果已经进入待核对状态时，关闭仍按既有规则保留原提交记录；保存确认后的正常退场继续执行。该修复没有新增追加评论的路径。

源码位置：[关闭与组词等待](../../../web/src/QuickComment.jsx)、[组词与关闭回归](../../../web/src/QuickComment.test.jsx)、[连续操作回归](../../../scripts/test-quick-comment-keyboard-safety.js)。

## 本次验证结果

- 修复前的专项测试复现组词结束后读取旧正文、组词关闭失败后正文回退、同一轮事件内保存被提前关闭，以及键盘隐藏先于组词结束时快照过早取得。
- 完整前端测试（228 项）、快速输入专项测试（45 项）和 Node.js 回归脚本（57 个）均通过。人工复读改动、语法和差异检查通过。
- 原生模拟完成120轮连续操作：80次草稿重开均恢复最终正文；40次保存产生40条评论，80次提交重放未增加额外评论；240个迟到的草稿或关闭请求被拒绝，旧定时器没有关闭新窗口或转移焦点。
- 包内 Chromium 在桌面、手机、深色平板及减少动态效果下完成48轮连续打开关闭，另检查早提交、关闭回执丢失恢复和重新打开。正文、模式及实际追加次数均符合预期。
- 包内 Chromium 与原生源码联合模拟验证正常及减少动态效果下的组词完成、关闭、重开恢复，以及关闭请求未送达后保留最终正文并再次关闭，未额外添加评论。
- 包内保存失败、部分写入核对、同标识重试、回执丢失、乱序草稿与模式记忆回归通过。
- 隔离构建和ZIP检查通过；安装包包含35个文件，25个JavaScript文件语法检查通过。

浏览器验证和原生模拟分别属于自动检查，不能替代真实 iPad、iPhone 的输入法与宿主通知顺序验收。
