# 混合格式原生接口调查

日期：2026-11-15。范围：局部加粗评论只修改文字色、背景色时，保留正文及分段字体。宿主为 MarginNote 5.1.0（51007）Mac。结论：RTF 层面的改色保粗体已经验证，但当前插件导出接口中没有找到可可靠接入的写回入口；本轮未开放混合格式编辑。

## 已验证的能力

独立 AppKit 样本为“普通文字｜局部加粗｜普通文字”。常规文字采用 PingFangSC-Regular，中间文字采用 PingFangSC-Semibold。仅修改文字颜色为 `#315D92`、背景为 `#D7EBFF`，重新导出并读取 RTF 后，正文、字体名称、字号和分段范围完全一致。

该结果证明原生富文本格式能够保留局部粗体，不能作为 MarginNote 插件已成功保存评论的证据。本轮没有写入或重建 MarginNote 评论，也没有使用当前普通文本重建流程处理混合格式。

## 宿主接口核对

读取当前应用的 JSBMbBookNote 完整 JSExport 协议，并在真实插件中检查实际绑定：

| 入口 | 结果 |
| --- | --- |
| `appendRichTextComment(text, style)` | 可调用；实际实现只读取统一的 fontName、fontSize、textColor 和 backgroundColor。没有接收原始 RTF 或分段属性的入口。 |
| `comments` | 实机属性有 getter，没有 setter，writable 为 false。 |
| `setNotesAndUpdateMediaList`、`setComments`、`appendComment` | 未导出给 MbBookNote 的插件对象，实机读取均为 undefined。不能把应用内部方法名当成可调用接口。 |
| 逐字段文字色、背景色方法 | 安装包中存在相应选择器，但所属类为 AIOCRFieldConfigController，不是卡片评论 API；MbBookNote 上不可调用。 |
| `NSAttributedString`、`NSMutableAttributedString` | 全局对象存在，但创建或转换富文本不能补足评论写回接口。 |
| `paste()` | 可调用；实际实现读取 generalPasteboard 并发送 DragToNote 界面通知，返回类型为 void。该路径依赖系统剪贴板及界面处理，不是直接更新指定评论 RTF 的接口。本轮未调用，也没有访问剪贴板，不能将该路径记为成功或失败的分段保存测试。 |

实际插件读取混合样本的前后 RTF，均正确识别为局部混合格式。只读检查前后，专用验收卡片的原有评论未变。

当前开发者站的[添加批注](https://dev.marginnote.com.cn/api-reference/卡片与摘录/添加批注)和[更新批注](https://dev.marginnote.com.cn/api-reference/卡片与摘录/更新批注)也未列出原始 RTF 或分段属性参数。该资料属于网页面板接口，仅作补充，不替代经典插件 JSExport 与实机绑定结果。

## 处理结果与边界

保留混合格式保护，避免通过统一样式重建评论而丢失局部粗体。当前结果不等于 RTF 无法改色，也不把未测试的私有实现或界面粘贴路径宣称为不可行。可靠接入需要宿主提供按评论定位、接受 RTF 或分段属性，并能确认保存与撤销结果的写入能力。

临时探针已经移除，诊断偏好已清理。测试前安装包逐字节恢复，现有菜单、图标和面板高度改动保留；原学习集、模板和文档第 65 页保持。没有新增业务代码、推送或发布。
