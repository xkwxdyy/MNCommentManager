## 操作与范围

评论旁提供格式刷、复制、编辑和粘贴入口。格式刷采用当前评论的格式，处理同一卡片的其他 HTML 评论；复制保存独立格式快照，粘贴可以跨卡片使用。一次性格式刷不会改写已复制的格式。“标题源”可见标签已移除。

原生富文本编辑支持正文、换行、统一字体、字号、自定义文字颜色及背景颜色。普通文字和简单 Markdown 可以在预览后转为原生富文本；Markdown 采用显示文字。图片、公式、表格、嵌套列表及其他复杂结构先阻止转换。原生 RTF 与网页渲染 HTML 分别判断，附带 Cocoa HTML 预览缓存的 RTF 仍属于原生富文本。

格式快照在插件运行期间跨卡片保留。每张卡片维护独立撤销记录；批量操作可以整次恢复原类型、正文、Markdown、格式、字段和顺序。外部继续编辑后，旧预览与旧撤销记录拒绝写入。无法完整保留的混合样式、作者信息及附加元数据继续限制。

## 原生兼容修复

原生编辑样本同时保存 `rtf`、`html` 和 `htmlSize`。旧实现把 `html` 和 `htmlSize` 当成未知元数据，导致编辑入口禁用；能力判断也不应要求 RTF 评论没有 HTML 缓存。修复后以有效 RTF 为样式依据，重建时采用原生追加接口。

原生粗体样本的字体表为 `Helvetica-Bold`，正文还带有 `\b`。解析器现保留具体字体名称，允许可完整表达的统一粗体和斜体；不能对应到可写字体的标记、局部混合格式及额外段落格式继续拒绝。关闭下划线、正常字符缩放、灰度颜色和未引用的扩展颜色项不再被误拒。

字体切换可能把原来的字节编码改成 Unicode。正文核对现按实际字符比较，并通过原生 NSString 解码与逐字节重编码确认无损；未知编码保持独立标识，不放宽正文不一致保护。GBK 的普通 ASCII 尾字节和转义字符也纳入同一字节流。

实测还发现原生撤销分组可能吞掉 JavaScript 回调异常。`UndoGroupingHelper` 在回调内捕获原异常，并在原生调用返回后重新抛出，防止失败操作继续返回完成。

Markdown 分类以原生标记和完整正文为依据。旧版 MNUtils 的 `^#\S` 标签结果会重新核对，一级至六级标题、代码、缩进与井号正文不再误归为标签；真正中文标签、层级标签与多个标签继续支持。

- 原生卡片即时刷新已取得单窗口画面证据：应用格式后先只读回读，再关闭管理器，未再写入其他控制评论，卡片已经显示新颜色。后台 WebView 内容截图为空，页面布局以浏览器检查及真实 WebView DOM 证据为准。
- 补充 Mac 回归通过：带原生 HTML 缓存的评论改色和改正文、整段粗体复制到中文正文、改色后保粗，以及管理器内撤销。独立 AppKit 解码确认正文、字体和颜色；原始原生样本的全部属性及 RTF 字节未变。最终只读冒烟检查确认 GBK 边界与 Unicode 正文等价。
