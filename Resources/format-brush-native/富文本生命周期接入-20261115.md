## 操作与范围

评论旁分别提供格式刷、复制、编辑和粘贴入口。格式刷直接采用当前评论的格式，仅处理同一卡片的其他 HTML 评论；复制只保存格式快照，粘贴可以跨卡片使用。一次性格式刷不会改写已复制的格式。原有模块识别继续使用，“标题源”可见标签已移除。

HTML 编辑器支持正文、换行、字体、字号、自定义文字颜色与背景颜色，也可以恢复默认文字色或透明背景。颜色支持取色器和十六进制输入。草稿提供即时预览，保存失败保留输入，重复点击不会重复提交。新增 HTML 评论可以采用已复制的格式。

普通文字和简单 Markdown 可以在粘贴预览后转为原生 HTML。Markdown 转换采用显示文字；图片、公式、链接、表格、嵌套列表及其他复杂结构先阻止转换。统一格式之外的混合样式、作者信息、折叠标识及无法完整保留的元数据同样禁用。Markdown 数学识别与当前渲染器的标记边界一致，代码中的美元符号及转义文本不按公式处理。

复制格式在插件运行期间跨卡片保留，不依赖网页存储。每张卡片维护独立撤销记录；批量粘贴按整次操作恢复原评论类型、原始 Markdown、正文、格式、字段和顺序。外部继续编辑后，旧预览和旧撤销记录会拒绝写入。该能力属于评论管理器内撤销；系统撤销仍需单独验收。

## 实现与验证

`src/RichCommentLifecycle.js` 统一处理格式快照、预览、保存和撤销，调用原生 `appendRichTextComment`，不使用 `addHtmlTemplate`。评论集合只读，写入沿用已验证的追加、核对、排序及删除流程；修改正文前核对原 RTF 与文本镜像。保存与失败恢复结束后，复用既有宿主刷新方法。

网页层通过 `WebBridgeCommands` 使用原生数据。编辑期间卡片保持绑定，迟到的复制回执只更新全局格式快照，不覆盖目标卡片的撤销记录。独立原型直接复用正式 `App`、弹窗和编辑器，示例数据由模拟通信层提供，避免原型与正式交互分叉。
