# 双指选择中断恢复及选区覆盖

## 问题与复现

2026-10-11 自行审查时，通过共用手势测试和正式 React 交互测试复现：

- 活动手势遇到窗口失焦、页面隐藏、列表外取消事件时，选区未恢复，边缘滚动可能继续运行。
- 外部弹窗导致手势禁用后，未继续移动而直接抬手时，临时选区仍被保留。
- 显式取消后，尚未全部抬起的触点可以再次开始手势；抬手时触点身份变化也未被校验。
- 手势后的点击拦截同时影响键盘激活。
- 双指尚未抬起时，通过顶栏清空选区，后续移动重新选中了评论。

## 根因与修复

共用手势模块原先只在列表节点监听结束及取消事件，没有窗口和页面生命周期监听。禁用状态只在移动时检查，取消状态和触点身份校验也不完整。手势始终根据开始时的选区计算，没有识别明确的外部选区变更。

结束及取消事件现在由文档捕获；窗口失焦、页面隐藏和页面离开会恢复原有选区并停止动画。动画帧和抬手处理同时检查禁用状态及节点连接状态，取消后阻止尚未抬起的触点重新开始。触点身份变化会取消手势；键盘激活不受手势后的模拟点击拦截影响。

通过顶栏或键盘明确更新选区后，手势终止并保留新选区。后续移动、抬手、动画帧、取消和失焦均不覆盖该选区。演示和正式面板复用同一修复。

## 验证与待验收

正式前端 158 项测试通过，其中手势专项 15 项；共用手势规则 16 项测试通过。模块原生模拟及演示合并 45 项 Node 测试、独立演示 15 项 React 测试和 25 项浏览器回归通过。正式生产页面通过 7 组尺寸与主题检查和 12 项可信多点触摸模拟检查，页面无脚本错误。普通网页、Safari 11 目标 IIFE 和独立演示构建通过。

生命周期事件在自动测试中模拟；可信触摸检查仍属于 Chromium 模拟，不能替代真实设备。真实 iPad 和 MarginNote 的失焦、中断、滚动接管、捏合及宿主手势待验收，问题保持开放。
