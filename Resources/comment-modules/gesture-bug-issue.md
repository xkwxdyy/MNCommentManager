# Markdown 内容重绘导致双指连续选择中断

## 问题与复现

在当前卡片正式面板中，从 Markdown 评论正文开始双指纵向滑动。选区首次更新后，原触摸节点失去 DOM 连接，后续触摸事件无法继续传到评论列表。

自动交互测试已复现该行为：初始触摸目标为 Markdown 正文中的 `strong` 节点；首次选区变化后，`target.isConnected` 为 `false`。真实 iPad 与 MarginNote 宿主尚未验收。

## 根因与修改

`MarkdownCommentBody` 虽然缓存渲染后的 HTML 字符串，每次渲染仍重新创建传给 `dangerouslySetInnerHTML` 的对象。选区或状态更新因此重新生成内部 DOM。折叠后的 Markdown 摘要存在相同形式。

修改为按内容缓存完整 HTML 对象，使选区和手势状态更新保持原触摸目标连接。正文或摘要内容实际变化时仍重新渲染。演示与正式面板共用手势实现，并增加持续滑动和折叠摘要的节点稳定性测试。

## 验证与待验收

已通过自动交互测试复现并修复正文触摸节点断开，折叠摘要的持续滑动也已通过。正式前端完整 154 项测试通过，其中手势专项 12 项；共用手势规则 7 项 Node 测试通过。正式生产页面通过 7 组尺寸和主题检查及 9 项可信多点触摸模拟检查，无页面脚本错误。正式网页及 Safari 11 目标的 IIFE 隔离构建通过。详细结果记录在 `Resources/comment-modules/integration-validation.md`。

真实 iPad 与 MarginNote 的双指连续选择、系统滚动接管、捏合、边缘自动滚动及弹窗中断仍待验收；问题保持开放。本次不包含提交、推送或发版。
