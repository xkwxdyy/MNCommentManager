# 最新状态校验使 macOS 和 iPad 评论折叠入口消失

## 用户反馈

2026-10-11，最新开发修改后，iPad 的评论折叠按钮消失，右下角显示“批注折叠接口返回的状态不完整”。随后 macOS 也反馈按钮消失。iPad 宿主为 MarginNote TestFlight 4.5.0 build 60；macOS 完整构建号未提供。

## 调查与证据

源码相对已发布版本新增了卡片身份、归属标识及稳定标识校验。其中每条评论必须有非空 ownerNoteId，commentId 必须严格等于 JavaScript null 或非空字符串。现有折叠操作只使用索引目标，不使用归属标识或稳定标识。任一条评论被拒绝都会使整个卡片的 supported 变为 false，页面随之隐藏折叠按钮。

本机 Bridge 只读检查了截图对应的选中卡片。评论状态包含有效卡片身份、字符串版本、从 1 起的索引和布尔折叠状态；历史条目的 commentId 包含 null。该证据来自 HTTP JSON，未直接获取原生 JavaScriptCore 中空值的表示；原生空值转换或字段缺失是否触发截图中的错误，仍需宿主复验。

模拟测试覆盖缺失归属和稳定标识、原生空值对象表示；原新增校验会拒绝这些投影。已有版本与索引校验不依赖这些字段。

## 本地修复

- 索引操作停止强制校验未使用的 ownerNoteId 和 commentId。
- 保留卡片身份、版本、数组、连续索引及布尔状态检查。
- 状态异常明确标明字段路径和类型，不记录评论正文。
- 保存仍核对 persisted、请求数量、方向、变更数量和目标回读状态；不自动重试，不改动用户资料库。

前端完整测试 163 项、Node 53 个脚本、普通及 Safari 11 目标构建、隔离安装包构建和 ZIP 校验通过。最终包内网页通过桌面、平板、窄屏和深色窗口的模拟交互检查，无页面脚本错误。相关模块命令已补入 Bridge 生命周期测试清单，生产逻辑保持原样。
