# 批注折叠接口接入与工作流保存

批注折叠由 MarginNote 宿主保存。评论管理器使用原生接口，经现有 MNBridge 向网页面板提供状态和操作结果。工作流配置另存于插件文稿目录；配置保存与批注折叠属于不同的操作。

## 接口依据

来源为开发者于 2026 年 10 月 11 日提供的 [MarginNote Comment 折叠接口接入指南](MarginNote%20Comment%20折叠接口接入指南.md)。归档副本与 Downloads 中的原文逐字节一致，SHA-256 为 `51500d76beb05fb4648eaa91a28a260b15488de663097294985324c42d575337`。原文中的示例和宿主测试命令属于参考资料，宿主仓库的测试不作为本插件的验证结果。

原文补充并确认了此前宿主 revision `8451497ca7cb` 的接口核实记录。支持条件以方法存在和有效回执为准，不能仅凭 MarginNote 4 的名称判断支持情况。

## 现有接入约定

|事项|插件约定与实现位置|
|---|---|
|调用路径|`web/src/lib/mnBridge.js` → `src/WebBridgeCommands.js` → `src/CommentMutations.js` → `src/CommentFoldState.js`。网页保持现有 MNBridge，不直接调用原生对象。|
|原生读取|同时检测 `commentState` 与 `setCommentsCollapsed`；读取结果必须满足 `ok === true`，包含有效卡片身份、版本和批注投影。|
|索引|面板及工作流选择器使用从 0 开始的索引；适配器仅在调用宿主时转换为从 1 开始的索引。标题与原生摘录不参与批注折叠。|
|版本|提交面板展示时的 `revision`，原样传回。适配器提交前读取状态，仅比较版本，不用新版本替换旧版本。版本变化后需要刷新并重新选择。|
|目标|每次调用选择 1 至 200 条批注，拒绝空数组、重复或非法索引；方向必须是布尔值。当前实现使用文档允许的索引目标。稳定标识目标如在后续接入，仍须携带版本，且不得改写实际归属卡片。|
|引用卡|对显示卡片的原生对象调用接口，由宿主定位共享和本地批注的实际归属。|
|事务|宿主管理保存、独立数据库读回、撤销、失败回滚和刷新。插件不额外调用 `savedb`，不包装折叠撤销组，不直接改写批注存储字段。|
|成功判断|原生返回必须满足 `ok === true`、`persisted === true`；回执卡片身份、方向、请求数量、变更数量、归属列表及目标状态均需有效。幂等操作允许 `changedCount === 0`。|
|错误处理|保留宿主 `code`、`message` 和可选 `details`。面板及工作流显示错误码；诊断字段不用于计算折叠状态，也不假定失败已经恢复。|
|失败恢复|面板先清除旧选区并停用折叠操作，再尝试回读；回读失败时保持停用，成功刷新后恢复。插件不自动重试写入。|
|内容边界|折叠只改变显示状态。宿主接口的 `text` 是最多 4000 个 UTF-16 代码单元的摘要；面板完整正文和搜索继续使用原有内容读取流程。|

原生调用要求主线程、有效数据库卡片及可用保存和撤销上下文。历史学习集和只读存储不能写入。其他编辑应先完成；宿主保存可能同时提交已有待保存改动。

新版 `mn.api` 面板入口与原生入口返回格式不同。网页入口需要检查 `error` 和 `persisted`，使用 `confirm: true`；原生入口没有 `confirm`。当前插件不使用新版面板路由。后续改用该入口时，需要独立验证能力、路由放行和有效目标的 `confirm: false` 预检；`CONFIRM_REQUIRED` 表示未写入。

## 工作流配置与执行

`foldSelectedComments` 和 `unfoldSelectedComments` 是内置选择动作，不需要配置参数。保存配置时，动作下拉框中的待添加动作会随保存写入步骤；点击“添加步骤”后，该动作不再处于待添加状态，保存不会重复追加。待添加动作也参与未保存更改保护。

配置保存继续通过 `saveWorkflow` 写入 `documentPath/marginnote.extension.mncommentmanager/workflows.json`。`CommentWorkflowStore` 拒绝空动作或被规范化过程丢弃的步骤，原子写入后回读文件并核对内容。回读异常或内容不一致返回 `WORKFLOW_SAVE_UNCONFIRMED`；界面保留草稿和待添加动作，不自动重试。该错误表示保存结果不确定，不表示文件必然未写入。

管理器还核对回执中的步骤类型和动作标识，防止动作被替换而仍显示成功。已经保存为仅含选择器的工作流无法自动推断原本期望的动作，需要重新选择并保存；修复不会擅自修改历史工作流。

执行时，每个动作依据当前卡片重新应用选择器。折叠步骤独立调用宿主事务；其余连续修改步骤使用插件撤销组。批量执行不是跨卡片原子事务，部分卡片失败时，已成功的卡片可能已经保存；工作流会报告卡片级错误并停止后续步骤。

## 验证与宿主验收

本地回归入口：

```sh
npm run test:comment-fold
node scripts/test-comment-workflow-store.js
node scripts/test-bridge-error-correlation.js
node scripts/test-workflow-mutation-lifecycle.js
npx vitest run web/src/App.workflow-fold.test.jsx
```

自动化测试使用模拟宿主和隔离文件数据。测试覆盖索引转换、200 条边界、版本冲突、引用归属、幂等结果、异常回执、诊断传递、折叠步骤的独立撤销，以及选择动作后直接保存和重新打开工作流。构建应在隔离副本中执行，避免修改仓库的 `src/web-dist/`。

目标 MarginNote 构建仍需完成以下验收：

- 工作流选择折叠或展开动作后直接保存，关闭并重开，核对步骤名称；重启后再次核对。
- 执行单卡和多卡工作流，检查文字、图片、手写及音频批注的显示状态，保存后重新打开卡片。
- 对同一目标重复设置相同状态，检查幂等结果；执行混合工作流，检查折叠步骤前后的撤销与重做。
- 在选择之后编辑或排序批注，再提交旧版本，确认拒绝操作并要求重新选择。
- 对引用卡检查共享与本地批注归属、原卡同步和刷新。
- 模拟保存失败及回读失败，核对具体错误码、草稿保留、选区清除和操作停用。

折叠不承担访问控制或复习遮答案功能。展示范围由宿主能力决定；未完成实际宿主验收时，自动化测试不能证明全部编辑或复习视图的行为。
